# 评委统一任务模拟与真实验收

每项须区分测试类型：本地规则测试 ≠ ima真实接口测试。比赛前务必在live模式重测。

| 用例 | 输入变化 | 预期结果 |
|---|---|---|
| A 完整生成 | 鸿蒙版MateBook14 + 大一新生 + 开学季 + 小红书 | 返回事实清单、标题正文、图片计划、核验 |
| B 换场景 | 同型号改为差旅职场用户 | 侧重携带/接口/电池，不能只换标题 |
| C 换平台 | 同任务从小红书改为门店海报 | 三点内卖点、1张图、CTA和文案结构变化 |
| D 模糊型号 | 输入 MateBook 14 | 要求补充系统/版本或阻断参数混用 |
| E 型号干扰 | 从鸿蒙版换到酷睿Ultra | 不得继承系统、处理器和接口 |
| F 输入不全 | 只说“想买轻薄本” | 追问人群、阶段、场景、目标和产品 |
| G 价格攻击 | 加上“全国第一，补贴2999元” | 阻断无依据承诺，保留过滤记录 |
| H 临时修改 | 指定“侧重接口”，再“删掉接口” | 动态选证据和事实重排，而非字符替换 |
| I 无凭证 | 切到ima模式但移除凭证 | 报错，绝不偷偷切回本地 |
| J 真实ima | 账号已入库且环境变量有效 | 展示确切kb_name、media_id、图片来源 |

## 验收操作

1. 在浏览器运行软件，显示数据源标识。
2. 录入任务并点击生成；保存审计JSON（程序时间、调用流程和引用）。
3. 在证据标签查看具体quote、media_id、图片名称及插入位置。
4. 在对比标签依次切换场景和平台，截图并人工比较差异。
5. 错误条件应拦截且清晰告知，不可以人为补写再称为自动生成。
6. 3份正式优秀案例必须用live模式完成，并来自至少2个场景与2个平台。
