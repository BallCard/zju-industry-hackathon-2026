# GitHub与魔搭部署步骤、提交安全检查

## 1. GitHub（须由拥有账户权限者操作）

确保README、代码、测试、说明书、三组真实案例完整。运行：

    npm run check
    npm test
    git status --short
    git ls-files

新建公开Github仓库后，使用自己的账号配置远端并推送。项目没有访问你的GitHub凭证，也不会虚构已上线网址。当前用户已授权的 `data/kb/` 知识库副本随 PC Studio 代码发布；仍严禁上传 `.env`、API Key、Client ID 及其他未授权资料。

## 2. 魔搭创空间 Docker 部署

本项目包含Dockerfile、ms_deploy.json。魔搭Docker应用监听必须绑定0.0.0.0:7860。

构建上下文为 `apps/pc-studio/`，需同时包含 `backend/`、`frontend/`、`data/`、`docs/` 和 `package.json`。容器启动入口为 `node backend/server.js`，页面与API仍由同一服务提供；不能只上传backend目录。可从应用目录验证：

    docker build -t pc-studio .
    docker run --rm -p 7860:7860 pc-studio

1. 登录并创建Docker类型创空间，按平台要求完成绑定和实名操作。
2. 推送当前项目源码至创空间仓库。
3. 在Secrets中设置IMA_OPENAPI_CLIENTID与IMA_OPENAPI_APIKEY；普通配置IMA_KB_NAME填赛题指定共享库名称。
4. 如启用语言模型，配置LLM_MODEL、LLM_BASE_URL和作为Secrets保存的LLM_API_KEY。
5. 检查Build和Run日志，实际访问公开URL验证/、/api/health、/api/ima-check和完整live生成。
6. 使用无登录浏览器验证评委期间能打开；检查实际资料来源，不能伪造media_id或本地回退。

当前魔搭规则与文档请参阅：https://modelscope.cn/docs/studios/docker

## 3. 比赛提交要求

初赛：GitHub源码、魔搭应用页面和作品说明书。
复赛：继续提交上述材料+连续真实Demo运行录屏；至少三组优秀结果，覆盖2种业务场景及2个平台。
决赛：现场可运行系统+展示资料。具体赛程及奖项由组委会发布。

## 4. 禁止伪造的部分

当前GitHub与魔搭地址未发布，不能预填虚构链接。ima共享库尚未用参赛账号确认，因此examples中的本地演示只用于说明研发成果。Demo视频须实际录制真实运行。
