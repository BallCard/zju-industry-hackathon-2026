# GitHub与魔搭部署步骤、提交安全检查

## 1. GitHub（须由拥有账户权限者操作）

确保README、代码、测试、说明书、三组真实案例完整。运行：

    npm run check
    npm test
    git status --short
    git ls-files

新建公开Github仓库后，使用自己的账号配置远端并推送。项目没有访问你的GitHub凭证，也不会虚构已上线网址。当前用户已授权的 `data/kb/` 知识库副本随 PC Studio 代码发布；仍严禁上传 `.env`、API Key、Client ID 及其他未授权资料。

## 2. 魔搭创空间 Docker 部署

本项目的 `Dockerfile`、`.dockerignore` 和 `ms_deploy.json` 位于 GitHub 仓库根目录。魔搭 Docker 应用监听必须绑定 `0.0.0.0:7860`。

Docker 构建上下文必须是 GitHub 仓库根目录；Dockerfile 会从 `apps/pc-studio/` 复制 `backend/`、`frontend/`、`data/`、`docs/SYSTEM_PROMPT.md` 和 `package.json`。容器启动入口为 `node backend/server.js`，页面与 API 仍由同一服务提供；不能只上传 `apps/pc-studio/backend` 目录。可在仓库根目录验证：

    docker build -t pc-studio .
    docker run --rm -p 7860:7860 pc-studio

默认 local 模式使用镜像中的授权知识库 `data/kb/`，无需 ima 或 LLM 凭证即可生成开发演示图文。根目录 `.dockerignore` 仅放行运行文件和已授权随项目发布的知识库副本，排除外部私有知识库、凭证、测试输出和 Git/worktree。

正式 ima 验收时，按仓库根目录 `.env.example` 创建 `.env`，使用 `docker run --rm -p 7860:7860 --env-file .env -e DEFAULT_DATA_MODE=live pc-studio`，只在运行时注入凭证。云端不能依赖本机私有 TXT；本地演示不替代真实 ima 记录，实际凭证仍不得提交。

1. 登录并创建Docker类型创空间，按平台要求完成绑定和实名操作。
2. 推送当前项目源码至创空间仓库。
3. 在 Secrets 中设置 IMA_OPENAPI_CLIENTID 与 IMA_OPENAPI_APIKEY；普通配置 IMA_KB_NAME 填赛题指定共享库名称，并设置 DEFAULT_DATA_MODE=live。Dockerfile 路径使用根目录的 Dockerfile，构建上下文使用整个仓库。
4. 如启用语言模型，配置LLM_MODEL、LLM_BASE_URL和作为Secrets保存的LLM_API_KEY。
5. 检查Build和Run日志，实际访问公开URL验证/、/api/health、/api/ima-check和完整live生成。
6. 使用无登录浏览器验证评委期间能打开；检查实际资料来源，不能伪造media_id或本地回退。

当前魔搭规则与文档请参阅：https://modelscope.cn/docs/studios/docker

## 3. 比赛提交要求

初赛：GitHub源码、魔搭应用页面和作品说明书。
复赛：继续提交上述材料+连续真实Demo运行录屏；至少三组优秀结果，覆盖2种业务场景及2个平台。
决赛：现场可运行系统+展示资料。具体赛程及奖项由组委会发布。

## 4. 禁止伪造的部分

当前GitHub与魔搭地址未发布，不能预填虚构链接。ima共享库尚未用参赛账号确认，因此examples中的本地演示只用于说明研发成果。Demo视频须实际录制真实运行。
